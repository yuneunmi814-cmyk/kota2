원천 API 하나가 실패해도 다른 원천은 사용할 수 있게 했다. 대표 원천 ID가 바뀌어도 기존 `festival_sources` 연결을 읽어 보정을 이어 적용한다. 새 테이블·마이그레이션은 필요 없다. 해당 테이블이 없는 구 스키마에서는 직접 ID 보정만 사용하며, 다른 연결 조회 장애를 테이블 없음으로 숨기지는 않는다.

## 검증

- 최종 축소 코드에서 자동 테스트 63/63 통과. 실제 pipeline/web export에 신규 5건 보정과 원본 불변 검증 포함.
- web·pipeline TypeScript 검사 통과.
- lint 오류 0, 기존 경고 2건(홈 nextMonth 미사용, Poster img).
- 최종 코드 전체 빌드 성공은 주장하지 않는다. 이전 커밋 `150ff7a`의 Linux CI는 성공했지만 이번 축소 커밋의 결과는 아니다.
- Windows 로컬 전체 빌드는 기존 슬러그의 `<가자갯벌도시>`가 파일명 제한에 걸렸다. 이를 우회하려고 ID·URL을 변경하지 않았다.
- 병합 전 CTO 환경에서 production build와 목록→상세 날짜 일치, 인기순/거리순, 구 원천 ID 보정의 실제 DB 결과를 확인해 달라.

## 제외·보류

후기 식별자 전환, SQL 초안, 상세 로더·메타데이터 분리, 계측, 새 CI workflow는 최종 diff에서 제외했다. 기존 후기 코드·DB 스키마는 그대로다. 제외한 중간 작업은 COO 로컬 `작업보관`에 보존했다.

장기 후보 96건 중 근거를 정리한 것은 14건이며 신규 날짜 보정은 5건이다. 나머지 82건을 전수 검증했다고 보고하지 않는다. 태국 이용자 전용 순서나 새 분류 정책은 팀 결정 없이 추가하지 않았다.

새연교 공연은 [제주문화예술재단](https://www.jejunolda.com/2020/nolda/all.htm?act=view&seq=16114)의 주소가 남성중로 40으로, 현재 43과 다르다. 이번 주소 보정은 보류했다. 주소만 변경하면 안전 규칙상 기존 좌표가 지워지므로 실제 행사 지점 좌표까지 확인한 후 별도 보정해야 한다. 날짜 4/25~10/31은 유지 대상이다.

## 외부 작업 이력

범위 축소 전에 공개 Supabase URL·publishable key를 GitHub Actions repository variables로 등록하고 기존 CI를 재실행한 이력이 있다. 관리자 비밀키나 DB 데이터는 변경하지 않았다. 이 변수는 이번 코드 정리로 삭제하지 않았으며 추가 설정 변경도 하지 않았다. Docker Desktop을 실행한 적은 있으나 DB 컨테이너 생성·SQL 실행은 없었다.

메인 병합 및 실제 운영 반영은 CTO 담당이다.
