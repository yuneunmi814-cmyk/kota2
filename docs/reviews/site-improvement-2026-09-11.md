# KOTA 전체 개선 — 실행 결과와 다음 작업

> 2차 최신 결과: [주말 누락27건 후속](2026-09-11-official-media/RESULT.md). 아래 수치는1차 시점 기록이다.

기준: 2026-09-11 KST. 개선 브랜치 `codex/site-quality-20260911`.
운영 사이트를 확인하고 코드에 반영한 1차 개선이다. 운영 DB 갱신·main 반영·배포는 하지 않았다.

## 1. 포스터: 숫자가 줄어든 이유와 남은 일

| 측정 | 운영 화면 최초 조사 | 개선본 공개 데이터 조회 |
|---|---:|---:|
| 진행·예정 카드 | 560 | 554 |
| 이미지 없는 카드 | 171 | 165 |
| 이번 주말 카드 | 121 | 119 |
| 주말 이미지 없는 카드 | 29 | 27 |

최초 운영 화면과 07:19 개선본 조회는 시점이 다르다. 같은 화면 범위의 참고 비교이며 전체 이미지 URL의 정상 응답을 검증한 숫자가 아니다. 개선본은 실제 화면의 DB+실시간 원천+정정 적용 결과를 사용했다.

6쌍(잠수교·달성대구현대미술제·남한산성·계룡군문화·천안흥타령·영주풍기인삼)을 날짜·지역·이름으로 확인해 한 카드로 묶었다. 이미지가 있는 행을 대표로 택한 결과이며 **새 포스터 6장 확보라는 뜻은 아니다.** 기존 주소·ID·후기를 삭제하지 않는다. 근거가 부족한 다른 중복 의심 건은 유지한다.

갤러리 API를 복사 데이터에서 40회 조회했다. 사진 보강은 있었지만 **새 대표 이미지 확보는 0건**이었다. 이 복사본의 누락 170건 모두 직접 연결된 TourAPI ID가 없었다. 따라서 갤러리 API 호출 횟수만 늘리는 방법은 우선 해법이 아니다. 복사본 데이터를 운영에 덮어쓰지 않았다.

### 구현한 재발 방지

- 실패 기록을 영구 유지하지 않고 임박 행사부터 재시도한다. 주간 실행의 실제 재시도 간격은 주간 스케줄에 제한된다.
- WebP·확장자 없는 이미지 주소를 판별하고 정상 HTTP 주소를 임의로 HTTPS로 바꾸지 않는다.
- 공식 홈페이지에서 이미지 후보를 모으는 별도 명령을 추가했다. 후보에는 출처·행사 날짜·확인일이 붙고 자동 게시되지 않는다.
- 해당 회차 및 사용 근거를 확인한 이미지 목록을 적용하며 새 이미지는 응답 검사 후 반영한다.
- 다음 수집에서 기존에 보강한 같은 회차 이미지·사진이 사라지지 않게 보존한다.
- 주간 갱신에 갤러리·검수 이미지 적용·품질 집계를 연결했다. 이번에 운영 갱신을 실행한 것은 아니다.
- 이미지 없는 카드에는 실제 행사명과 상태를 보여준다. 공식 포스터처럼 보이는 임의 이미지를 제작하지 않는다.

### 포스터 후속 작업 순서와 완료 기준

1. **주말 누락 27건 먼저:** 공식 행사 상세 공지 확인 → 해당 연도·회차 확인 → 이미지 원본·사용 근거 기록 → 이미지 정상 응답 확인 → 적용 후보 작성. 종료된 행사는 날짜에 따라 우선순위를 낮춘다.
2. **30일 이내 시작 행사:** 같은 절차로 처리하고 잘못 연결된 TourAPI ID를 확인한다. 이름만 비슷하다고 연결하지 않는다.
3. **나머지 165건 및 지난 회차 이미지:** 현재 회차 포스터, 공식 행사 사진, 이미지 없는 정보 카드 순으로 처리한다. 없으면 사유와 다음 확인일을 남긴다.
4. **반영 후 재검사:** 대표 이미지 수뿐 아니라 깨진 주소·다른 행사 이미지·지난해 포스터 오표시도 확인한다.

완료 기준은 임의의 달성률이 아니라 각 누락 건에 `확보 / 공식 미공개 / 출처 미확인 / 사용조건 확인 필요 / 연결 실패` 중 처리 결과가 있고, 확보된 이미지는 실제 목록·상세에서 열리는 것이다. **165건 전부 확보는 아직 미완료다.**

- web/pipeline TypeScript 검사 통과. lint 오류 없음; 외부 이미지의 기존 img 사용 경고는 남는다.

- 실제 브라우저: 9/12~13·서울 26건, 상세 이동 후 뒤로가기에서 날짜·지역 유지, 달력 서울 선택과 날짜별 결과 확인.

- 전체 이미지 건강 검사, 실제 단말 로그인·지도, 운영 검색 수집·속도는 별도 검증 필요.

## 5. 실행 경로

`web/scripts/quality-snapshot.ts`는 화면과 같은 공개 데이터 읽기 전용 집계다. `pipeline/src/audit-quality.ts`는 저장된 파일 기준 집계이므로 둘의 숫자를 섞지 않는다.

- `pipeline`: `npm run discover:images` → `data/image-candidates.json` 검수 후보 생성(기본 10행사).
- 검수 후 `web/data/reviewed-images.json`에 외부 ID별 `startDate`, `endDate`, `reviewedAt`, `rightsBasis`, `images: [{url, from, w, h}]` 기록.
- `npm run scrape`는 로컬 축제 파일에 검증된 이미지를 적용한다. `npm run push`는 운영 쓰기이므로 별도 백업·검증 후 실행한다.
- `npm run audit:quality`는 로컬 집계만 출력한다.

원본 작업 폴더의 사용자 변경과 운영 DB는 그대로다. 이 브랜치의 변경 파일만 커밋한다.
