### CR-01 · DB 미등록 신규 축제 상세 반환 누락

### CR-03 · 사용자 데이터 연결의 영속 ID 전환 미완

- 위치: `web/lib/reviews.ts:45,69`, `web/components/detail/Reviews.tsx:104~105`, 상세 `page.tsx:81`; `supabase/stable-festival-ids-draft.sql` 후반.
- 조건: 같은 festival_uid의 대표 externalId가 A에서 B로 바뀌고 기존 후기가 A에 연결돼 있음.
- 실제 코드: B 상세는 `reviewsOf(B)` 및 `festival_rating.festival_id=B`를 조회. source mapping을 통해 A의 후기를 합치지 않음. 쓰기도 festival_id만 보내며 conflict key도 출처 ID와 사용자 ID.
- SQL은 festival_uid 칼럼 및 기존 행 backfill을 추가했지만, 저장소 SQL에서 신규 후기의 UID 자동 채움과 읽기 전환을 확인하지 못함.
- 영향: 주소는 별칭으로 살아도 후기·평점 연결은 따로 끊길 수 있음. 현재 운영 후기 손실을 확인한 것은 아님. 운영에 별도 트리거가 있는지도 미검증.
- 수정 방향: 사용자 데이터 읽기·쓰기·중복 제약을 영속 UID 기준으로 단계 전환하거나, 과도기에는 같은 UID의 출처 ID를 모두 조회. 외래키·RLS·집계 뷰를 함께 검토.
- 수락 조건: A→B 전환 전후 후기 건수·평점·동일 사용자 중복 방지가 동일. 기존 데이터 삭제 없이 테스트 DB에서 확인.

## Standards

명시적 저장소 규칙 위반은 확인하지 못했습니다. 공식 도메인·externalId 식별·trailingSlash 유지 규칙은 검토 범위에서 지켜집니다. 린터가 처리할 항목은 제외했습니다.

판단성 개선점 1건: `web/lib/absorbed.ts:22`의 SAME 매핑은 `pipeline/src/lib/match.ts:19`와 중복됩니다. **Duplicated Code / Shotgun Surgery 휴리스틱**이며, 코드에도 한쪽만 수정하면 분류가 갈라진다는 경고가 있습니다. 공유 데이터 또는 동등성 테스트를 권장합니다. 현재 오동작을 입증한 버그는 아닙니다.

## Spec

1. “신규 slug의 배포 후 동작이 정해져 있다”: 신규 실시간 축제 상세 누락 조건이 존재합니다(CR-01). 운영에서 해당 조건인 축제 건수는 미검증.
2. “수집 출처가 바뀌어도 URL, 리뷰, 행동 로그의 축제 연결이 유지됨”: UUID/source mapping은 있지만 후기 읽기·쓰기의 출처 ID 의존이 남습니다(CR-03).
3. “상세 한 건 조회”: 순위의 전량 호출과 누적 횟수 분기가 단건 분리를 우회합니다(CR-05·06).
4. “loader, view-model, metadata, UI section 분리”: 순수 조립은 분리됐지만 조회 조율·metadata·다수 JSX는 page에 남습니다. 잔여 구조 작업이며 파일 길이만으로 버그라 판단하지 않습니다.

정당화되지 않은 범위 확장은 발견하지 않았습니다. Standards는 판단성 개선 1건(강제 위반 0), Spec은 주요 미완/회귀 4개 묶음입니다. 각 축의 가장 큰 이슈는 각각 중복 매핑 유지 부담과 신규 상세 누락·사용자 연결 미완입니다. 두 축은 별도로 판단합니다.
