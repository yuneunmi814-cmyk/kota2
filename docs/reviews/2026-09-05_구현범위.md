# COO 데이터·큐레이션 및 상담 후속 구현

사용자 승인: 2026-09-05. 기준 df7f6c2. 작업 브랜치 coo/festival-data-curation-review-2026-09-05.

## 승인된 설계

1. 원천 수집 → 복원 → 공식 정정 순서를 보장한다. 정정은 웹 실시간 병합 후에도 유지한다. 기존 이름 기반 표는 호환하되 고유 ID·연도 조건으로 오적용을 방지하고, 이름 다중 일치는 조용히 첫 행에 쓰지 않는다. 주소/좌표/지역 정정도 지원한다.
2. DB 미등록 live 축제는 목록에 나온 경우 상세도 찾을 수 있어야 한다. 없는 ID는 404. 요청 횟수를 빌드 감지로 쓰지 않고, 순위는 상세 사진·번역 전량 조회를 하지 않는다.
3. 후기의 출처 변경 연결은 영속 ID/source mapping 계약으로 보완한다. 기존 데이터는 삭제하지 않는다. 필요한 DB 변경은 별도 SQL·실행 순서·검증 절차를 PR에만 포함한다. 운영 DB에는 적용하지 않는다.
4. 시작일순·인기순은 상시 행사를 뒤에, 거리순은 실제 거리를 유지한다. 국적 추측 가중치는 만들지 않는다. 여행 날짜·지역·관심 테마 기반 선택을 유지/보완하고 태국어 포함 네 언어에 동일한 규칙을 적용한다. 인기순 대리지표의 한계를 설명한다.
5. 상담 잔여 항목: 날짜/상시/장기 경계, 외부 API 장애 격리, 신규 상세 계약 테스트, CI 검증·측정, 상세 loader/metadata/UI 경계 및 달력 조회 범위를 점검하고 목적에 맞는 최소 변경으로 보완한다.
6. 공식 자료 대조는 30일 초과부터. 공식 자료 충돌·미공개 일정은 변경하지 않고 보류 근거를 기록한다. 96개 후보를 전부 확정했다고 주장하지 않는다.

## 전역 제약

- 공식 도메인 ko-ta.co.kr. trailingSlash 유지. externalId 경로 호환 유지.
- main 수정/푸시/머지 금지. 작업 브랜치 푸시와 PR 생성은 승인됨.
- 데이터 삭제, 운영 DB 변경, 파이프라인 all/push, 비밀값 출력 금지.
- 원본 stash 보존. 기존 docs/reviews 자료는 검토 당시 기록으로 보존.
- 회귀 테스트 RED → GREEN 기록. 테스트/타입/린트/가능한 빌드 검증과 한계를 구분한다.

## 검증 기준

- 공식 정정된 날짜/주소는 카드와 상세에서 동일하게 보인다. 정정 없는 데이터는 live 갱신 유지.
- 복원 대상의 정정된 종료일로 적격 판정한다. 연도 다른 동명 축제는 수정하지 않는다.
- cold/warm/missing 상세, 9회 이상 호출 및 순위 조회가 동일한 계약을 따른다.
- 대표 ID A→B 변경 전후 후기 조회·평점·중복 방지가 유지된다. 실제 DB 실행 전에는 SQL 검증 미실행으로 표시한다.
- 상시 300일·장기 60일 경계, 상시 고득점과 가까운 거리, 필터 조합 회귀 보호.
- PR에 수정 완료/공식 대조 보류/CTO DB 적용 필요를 별도 표시한다.
