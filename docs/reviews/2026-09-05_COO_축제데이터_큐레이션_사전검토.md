### 정정 승인 기준

1. 서비스 상세 URL·고유 ID·현재 날짜·장소를 기록한다.
2. 동일 연도·동일 행사의 주최기관/지자체 상세 공고를 확보한다. 홈페이지 첫 화면 링크만 남기지 않는다.
3. 공식 자료 간 충돌, 취소·변경, 정기 회차형 프로그램은 따로 기록한다. 미확정 값을 추측해서 채우지 않는다.
4. 날짜 오류와 운영일 표현 문제를 구분한다. 매월 공연을 하는 프로그램의 시작~종료 범위를 하루 축제로 바꾸면 안 된다.
5. 근거가 확정된 건만 정정표 후보에 넣고 단일 대상에 적용되는지 검사한다.

## 3. 정정표 적용 경로 검토

근거: `pipeline/src/merge.ts:351~370`, `pipeline/data/seed/corrections.json`.

- 로더 타입과 대입 대상은 `name`, `startDate`, `endDate`뿐이다. `address`, 장소명, 위도·경도는 현재 반영하지 않는다.
- 매칭은 `merged.find(f => f.name.includes(c.match))`이다. 이름 일부가 같은 항목이 여러 개면 첫 항목만 선택한다. 추가 전에 매칭 개수와 고유 ID를 확인해야 한다.
- 정정표 설명은 공식 출처 원칙을 두지만 기존 한국유교문화축전 항목은 언론 기사 링크를 사용한다. 날짜가 틀렸다고 단정하는 것이 아니라, 직접 공식 근거로 보완할 필요가 있다는 뜻이다.

권고: 날짜 정정 PR과 장소 정정 지원 PR을 분리한다. 장소 지원 시 주소·좌표·지역 파생값의 일관성 및 기존 정정표 호환성 테스트를 포함한다. `npm run all` 등 번역 비용 또는 DB 쓰기가 포함된 전체 파이프라인은 검증 명목으로 실행하지 않는다.

## 4. 큐레이션 구현과 결정안

### 4-1. 연중 행사는 어디에서 뒤로 보낼 것인가

근거: `web/lib/list-rules.ts:47~55, 104~112`, `web/lib/festival-fields.ts:68~82`.

- 날짜순: 진행 중 단기 → 예정 단기 → 장기 → 상시.
- 인기순: `pop` 내림차순. 상시 여부를 보지 않는다.
- 좌표가 있는 거리순: 거리 오름차순. 상시 여부를 보지 않는다.
- 현재 상시 판정은 두 날짜 차이 **300일 이상**, 장기는 양끝 포함 **60일 초과**다. 검수용 ‘30일 초과’와 별개 기준이다.
- 진행 중·주말·월 필터에서는 상시를 단순 후순위가 아니라 제외한다. 예정 필터는 상시를 별도로 제외하지 않는다.

제안(미확정): 기본 추천에서 기간 한정 축제를 우선하되, 명시적인 거리순은 실제 거리 순서를 유지한다. 상설 관광행사도 원하는 이용자가 찾을 수 있도록 별도 보기 또는 포함 옵션을 논의한다. 모든 정렬에서 강제 후순위로 바꾸기 전 CTO·CMO와 적용 범위를 정한다.

### 4-2. 인기 지표를 어떻게 설명할 것인가

근거: `pipeline/src/popularity.ts:50~58, 118~127`.

- 비교 기간은 실제 작년 행사 공고가 아닌 올해 날짜를 **364일 전**으로 이동한 기간이다.
- 날짜 차이 21일 초과 행사는 유입 배율 산출에서 제외된다.
- 유입 데이터가 있으면 `round(max(0, visitorLift - 1) × 100) + 공식 지정 가점 100 + KFES 출처 가점 30`을 사용한다. 가점은 해당 조건을 충족할 때만 더한다.
- 데이터가 없으면 지정·KFES 가점에 `출처 개수 × 10`을 더한 대리지표를 쓴다.
- 따라서 실제 전년 개최 기간의 축제 방문객 수, 순수 증가배율, 좋아요 기반 인기도 중 어느 것과도 동일하지 않다.

제안(미확정): 순위 설명에 지역 유입 대리지표·가점·결측 대체를 명시한다. 실제 전년 개최일을 매칭할 수 없는 경우 추정임을 표시하거나 지표 사용을 제한하는 안을 검토한다. 지역 전체 방문 증가를 해당 축제가 유발했다고 단정하지 않는다.

### 4-3. 태국 이용자와 6개 테마

근거: `pipeline/src/lib/themes.ts`, `web/lib/listData.ts`, `web/lib/list-rules.ts`.

- 테마는 `food/nature/heritage/music/family/night`이며 중복 분류가 가능하다. 분류 생성은 파이프라인, 목록 필터·정렬은 웹으로 분리되어 있다.
- 현재 목록 규칙 자체에는 태국 이용자용 가중치 입력이 없다.
- 확인한 CMO `02_TARGET_STRATEGY.md`는 타깃 세부 항목·우선순위가 아직 작성 예정 형태다. `05_CONTENT_STRATEGY.md`는 신뢰성과 여행 의사결정 지원을 강조한다. 이 두 문서에서 태국 선호 가중치의 확정 근거는 확인하지 못했다. 다른 조사 자료 전체를 확인했다는 뜻은 아니다.

제안(미확정): 태국어 선택만으로 국적이나 취향을 단정하지 않는다. 여행 날짜·희망 지역·관심 테마를 이용자가 선택하는 추천을 우선 검토한다. CMO 조사로 검증한 추천 묶음은 별도 편집형 큐레이션으로 제시하고 선정 근거를 관리한다.
