### 함께 보완한 부분

- **다른 지역의 동명 행사 누락:** 라이브 대조에 지역 조건을 추가했습니다. 이름과 기간이 같아도 다른 지역 행사이면 유지합니다.
- **원천 연결 조회 장애:** 연결 테이블을 읽지 못할 때 신규 행사를 전부 감추지 않고 제한적인 이름·지역·기간 대조로 돌아갑니다. 이때 이름이 다른 중복 원천은 다시 보일 수 있습니다.
- **장기 행사 표현:** 기존 60일 초과 기준의 진행 중 행사는 카드·상세에서 ‘운영 기간 중’으로 표시하고, 상세에 방문일 운영 여부·휴무 확인 안내를 붙였습니다. 종료일에도 당일 공연을 보장하는 ‘오늘 종료’ 배지를 붙이지 않습니다. 실제 회차·휴무 데이터 모델은 만들지 않았습니다.
- **절대 URL 정규화:** `absUrl`의 잘못된 정규식을 수정하고 HTTPS 형식을 지키면서 중복 슬래시를 정리하도록 검사했습니다.
- **Windows 빌드 오류 완화:** `< > :` 등 Windows 파일명 금지 문자가 있는 상세 ID는 Windows에서만 사전 생성 대상에서 제외합니다. Linux/Vercel 대상, 공개 URL, externalId는 바꾸지 않습니다. 해당 상세의 요청 시 렌더링은 200으로 확인했으나 Windows ISR 캐시 저장 경고는 남습니다.

### 검증 환경의 한계

- 빌드·로컬 서버는 실제 공개 Supabase 데이터를 읽었습니다. 공개 브라우저 설정만 자식 프로세스 메모리에 전달했고, 비밀 키·환경 파일을 저장하지 않았습니다.
- 로컬에 `TOURAPI_SERVICE_KEY`가 없어 해당 실시간 호출은 건너뛰었습니다. 따라서 운영의 모든 라이브 원천 조합을 검증한 것은 아닙니다. Kfes·표준데이터 라이브 반영은 실행됐습니다.
- 브라우저 검사는 390×844 Chrome 에뮬레이션입니다. 쓰기 요청을 차단했고 로그인·후기 작성·관리자 작업은 하지 않았습니다. 실기기 Safari/Android 검증은 별도입니다.
- 빌드는 기존 Edge Runtime 폐기 예정 경고를 출력합니다. 단위 테스트의 모듈 형식·TypeScript 변환 경고도 남습니다.
- Windows 특수문자 경로는 HTTP 200으로 열리지만 로컬 캐시 저장은 실패합니다. 이 변경을 ‘모든 Windows 경로 문제 해결’로 해석하면 안 됩니다.
- 실제 번역의 자연스러움에 대한 원어민 검수와 원천 데이터의 운영일·휴무 전수 확인은 하지 않았습니다.
- 생산 배포는 수행하지 않았습니다. CTO 머지·배포 후 운영 설정에서 재확인해야 합니다.

## 4. 독립 검토 결과

### 표준 기준 검토 (Standards)

스테이징된 변경에서 문서화된 표준 위반이나 확신할 만한 기능 회귀는 발견되지 않았습니다. 정식 도메인, trailingSlash, externalId 식별, Supabase 표시 출처를 유지합니다.

검토자가 공유 버튼의 불필요한 언어 추론 경로를 지적해, 유일한 호출부가 전달하는 `lang`을 필수 속성으로 바꾸고 추론 상태를 제거했습니다. 해당 테스트·타입·린트 검사를 다시 통과했습니다. 이후 Windows 경로 보완을 포함한 전체 작업 트리도 재검토했고 새 표준 위반이나 확신할 만한 회귀는 발견되지 않았습니다.

### 요구사항 기준 검토 (Spec)

첫 검토에서 두 가지를 지적받았습니다.

1. 장기 행사 안내가 상세에만 있고 카드 배지는 여전히 ‘진행중’인 점.
2. 원천 연결 조회 실패 시 별개인 신규 행사도 전부 사라질 수 있는 점.

둘 다 수정했습니다. 재검토자는 관련 테스트 23개를 다시 실행해 통과를 확인했고, 수정 부분에서 새 명세 위반을 찾지 못했습니다. 카드의 긴 안내는 툴팁이므로 터치 화면에서는 보이지 않지만, ‘운영 기간 중’ 배지와 기존 ‘기간 중 일부 날짜’ 문구가 표시됩니다. 상세에는 일정 확인 안내가 보입니다.
