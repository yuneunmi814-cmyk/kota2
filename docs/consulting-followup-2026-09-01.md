# KOTA 기술컨설팅 후속 작업 현황과 계획

기준 시각: 2026-09-01 18:57 KST

## 한눈에 보는 결론

컨설팅의 핵심은 화면을 다시 만드는 것이 아니라, 여러 화면이 함께 쓰는 규칙을 화면 밖 한곳에 두고 테스트로 지키자는 것이었다. 특히 축제 자체와 데이터 출처의 ID를 분리하는 일이 가장 중요하다.

## 컨설팅 우선순위

| 순서 | 컨설팅 과제 | 당시 중요도 | 현재 상태 |
|---:|---|---|---|
| 1 | JIMFF 404를 재현하는 테스트부터 만들기 | 즉시 | 완료 |
| 2 | 영속 `festivalId`, 출처 ID, 과거 주소 별칭 분리 | 즉시 | 과거 주소 응급 복구 완료, DB 구조 분리는 남음 |
| 3 | KST 날짜 계산을 한곳으로 모으기 | 즉시 | 완료 |
| 4 | 시작일·종료일·자정·주말 테스트 추가 | 즉시 | 완료 |
| 5 | `allFestivals()`를 목적별 조회로 분리 | 다음 | `listSlugs()` 완료, 목록 요약 조회가 다음 |
| 6 | 목록 필터·정렬을 화면 밖 순수 함수로 분리 | 다음 | 미착수 |
| 7 | `FestivalList`의 URL·스크롤·위치 상태 분리 | 출시 전 필수 아님 | 미착수 |
| 8 | 상세 페이지의 조회·SEO·화면 부분 분리 | 출시 전 필수 아님 | 미착수 |

컨설턴트는 1~3번을 당장 문제가 되는 구간으로 설명했고, 7~8번은 출시 전 필수 수정이 아니라고 명시했다. 현재 SSG+ISR 방식도 바로 바꿀 근거가 없으므로 유지한다.

## 지금까지 완료한 작업

- 과거 `kfes`·`manual` JIMFF 주소가 현재 상세로 308 이동하도록 복구했다.
- Supabase 페이지 조회에 고정 보조 정렬을 추가해 빌드 작업자마다 축제가 빠지던 문제를 해결했다.
- 서비스의 “오늘”을 `Asia/Seoul` 기준 공통 함수로 통일했다.
- 홈·목록·달력·관리자·라이브 API가 같은 날짜를 사용하도록 바꿨다.
- 주소·한글 이동 경로·자정·시작일·종료일·주말 테스트를 추가했다.
- 경로 생성과 사이트맵을 ID만 읽는 `listFestivalSlugs()`로 분리했다.
- 테스트와 전체 빌드, 로컬 HTTP 308/200 동작을 확인했다.
- 커밋: `8247312 fix: 과거 축제 주소와 한국 날짜 기준을 안정화`

## 남은 과제

### 마감 전 우선

1. 운영 DB의 실제 표·컬럼·행 수와 이미 끊어진 리뷰·로그 수를 읽기 전용 SQL로 측정한다.
2. `festival_ids`, `festival_sources`, `festival_route_aliases` 설계를 확정한다.
3. 파이프라인이 같은 축제에 기존 영속 ID를 재사용하도록 수정한다.
4. 경로 생성과 사이트맵을 가벼운 `listSlugs()` 조회로 분리한다.
5. 목록 요약 조회를 분리하되 TourAPI 실시간 호출 정책은 유지한다.

### 마감 후 또는 여유가 있을 때

1. 상세 한 건 조회와 라이브 보정 분리
2. 목록 필터·정렬 순수 함수화
3. 큰 목록·상세 컴포넌트 분리
4. 기존 린트 오류 5건 정리
5. 옛 텍스트 ID 컬럼 제거 — 비가역이므로 공모전 이후

## 앞으로의 작업 계획

| 단계 | 작업 | 안전장치 | 배포 영향 |
|---:|---|---|---|
| A | 실제 DB 현황 측정 | 읽기 전용 SQL | 없음 |
| B | 새 ID 대장·출처·별칭 표 추가 | 기존 컬럼 유지, RLS 적용, 백업 | 없음 |
| C | 현재 축제에 영속 ID 발급·이용자 데이터 연결 | 건수·누락·중복 검증 | 없음 |
| D | 파이프라인이 영속 ID를 재사용하도록 변경 | 한 주간 새 ID 증가량 관찰 | 동기화 작업에 영향 |
| E | 웹의 별칭 조회를 DB 기반으로 변경 | 기존 하드코딩 폴백 유지 | 배포 영향 있음 |
| F | `listSlugs` → 목록 요약 → 상세 한 건 순서로 조회 분리 | 단계마다 빌드·목록/상세 날짜 일치 테스트 | 점진적 |
| G | 옛 컬럼 정리 | 공모전 이후, 별도 백업 | 비가역 |

## ORCA 협업 구성

- `kota-id-audit`: 영속 ID 스키마·이전·롤백 검토, 읽기 전용
- `kota-query-audit`: 목적별 조회·캐시·빌드 위험 검토, 읽기 전용
- 메인 작업 폴더: 코덱스만 수정·검증·커밋

두 검토자는 서로 다른 ORCA worktree를 사용하므로 메인 코드와 충돌하지 않는다. Codex CLI가 ORCA 터미널 PATH에서 바로 잡히지 않아 Claude 읽기 전용 검토자로 전환했으며, 두 검토 모두 파일 수정 없이 완료했다.
