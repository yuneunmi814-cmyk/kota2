# 민간 축제 수집 계획 — 마누스 협업

**작성 2026-08-18 · 목표: 공공데이터에 없는 민간·유료 축제를 신뢰 가능한 상태로 채운다**

---

## 0. 왜 필요한가

블로그 하나를 확인하다 드러났다. 「옥토버페스트 2026 서울」(9/12~21, 마포구 문화비축기지)이 우리 목록에 없다. 9월 서울 축제 32건을 전수로 봐도 그 기간 마포구 항목이 없고, ‘옥토버’ 검색은 0건이다.

우리 데이터는 **한국관광공사 TourAPI + 지자체 공공데이터**만 쓴다. 민간이 여는 유료 행사는 그 목록에 애초에 안 올라온다. 그래서 통째로 빠진 덩어리가 둘이다.

| 빠진 덩어리 | 예 |
|---|---|
| 대형 민간 페스티벌 | 워터밤, 흠뻑쇼 |
| 유료 티켓 음악 페스티벌 | 록·EDM·재즈 페스티벌 |

「맥주축제」로 검색하면 거제·공주·서울 것이 나온다. **지자체가 여는 것만 잡힌다**는 뜻이다.

심사 관점에서 이건 구멍이다. 심사위원이 "9월 서울 축제"를 보다가 옥토버페스트가 없으면 데이터가 부실하다고 읽는다. 그 기간 서울에서 사람이 가장 몰리는 행사 중 하나다.

---

## 1. 방법 여섯 가지와 선택

| | 방법 | 비용 | 위험 | 채택 |
|---|---|---|---|---|
| A | 수작업 확인 후 `manual` 등록 | 반나절 | 낮음 | ✅ **검증 단계로** |
| B | 티켓 판매처 파싱 (인터파크·예스24…) | 며칠 | 이용약관·구조 변경·유지비 | ❌ |
| C | 그대로 두고 "공공데이터 기반"임을 밝힘 | 0 | 빈 곳은 빈 채로 | ✅ **병행** |
| D | **마누스에 수집 위임** | 마누스 크레딧 | 환각 — 검증으로 막는다 | ✅ **축** |
| E | 주최측 등록 창구 (축제 등록 폼) | 하루 | 스팸 — 승인제로 막는다 | ✅ **지속 장치** |
| F | 이용자 제보 (기존 `corrections` 확장) | 두 시간 | 낮음 | ✅ **지속 장치** |

**D를 축으로, A를 관문으로, E·F를 지속 장치로.**

B를 버리는 이유: 티켓 판매처는 구조가 자주 바뀌고 이용약관이 걸린다. 한 번 만들면 계속 고쳐야 하는데, 9/21까지 그럴 여유가 없다. 우리가 필요한 건 상시 파이프라인이 아니라 **한 번의 채움 + 이후 유입 창구**다.

C를 병행하는 이유: 아무리 채워도 민간 축제를 전부 담을 수는 없다. 빈 곳을 빈 채로 두되 왜 빈지 밝히는 편이, 다 있는 척하다 하나 걸리는 것보다 낫다.

## 2. 역할 분담

> **수집은 마누스, 판단은 여기.**

마누스는 넓게 훑는 데 강하고 사실 확인에는 약하다. 그래서 마누스에게는 **후보를 모으는 일만** 시키고, 실을지 말지는 여기서 정한다. 이 경계를 흐리면 8/17에 263건 걷어낸 일이 반복된다.

| | 마누스 | 여기 |
|---|---|---|
| 하는 일 | 넓게 훑어 후보 목록 만들기 | 출처 확인 · 중복 제거 · 병합 |
| 산출물 | 표 한 장 (출처 URL 필수) | `manual-festivals.json` |
| 못 하게 할 것 | "아마 열릴 것" 추정 | — |

**마누스가 출처 URL을 못 적은 행은 통째로 버린다.** 예외 없음.

### 운용 주의

- 마누스는 우리 쪽 MCP가 없어 **크롬에서 수동 조작**한다
- 입력창에서 **줄바꿈이 곧 제출**이다 — 아래 프롬프트는 반드시 **한 번에 붙여넣기**(Shift+Enter로 줄을 나누지 말 것)
- ⏰ **8/23 마누스 백업 기한** — 수집은 그 전에 끝낸다. 이후는 E·F로 유지

## 3. 마누스 출력 규격

우리 `manual` 소스 스키마에 1:1로 맞춘다. 그래야 받아서 바로 넣는다.

| 열 | 필수 | 설명 |
|---|---|---|
| `name` | ✅ | 공식 명칭 그대로. 줄임말·별칭 금지 |
| `startDate` / `endDate` | ✅ | `YYYY-MM-DD`. 하루면 같은 값 |
| `sido` / `sigungu` | ✅ | 「서울특별시」 「마포구」처럼 행정 표기 |
| `address` | ✅ | 도로명 또는 장소명 |
| `homepage` | ✅ | 공식 홈페이지 또는 예매처 |
| `instagram` / `tel` | | 있으면 |
| `fee` | ✅ | 「일반석 20,000원 / 프리미엄 200,000원(4인)」처럼 원문 |
| `organizer` | | 주최·주관 |
| `summary` | ✅ | 두세 문장. **홍보 문구 베끼지 말고 사실만** |
| **`sourceUrl`** | ✅✅ | **확인한 페이지 주소. 없으면 그 행은 버린다** |
| `confidence` | ✅ | `공식`(주최측 채널) / `예매처` / `언론` / `블로그` |

`confidence`가 `블로그`뿐인 항목은 여기서 재확인 전까지 안 싣는다.

### 담지 말 것

- **포스터 이미지 파일** — 민간 축제 포스터는 저작권이 있다. 우리가 복제하면 안 된다. URL도 받지 않는다(핫링크도 분쟁 소지). 사진은 「포스터 준비 중」으로 둔다
- 추정 날짜 — "매년 9월쯤"은 버린다. 확정 공지만
- 이미 끝난 회차

## 4. 배치 설계

한 번에 다 시키면 마누스가 얕게 훑는다. 셋으로 쪼갠다.

| 배치 | 범위 | 기대 건수 |
|---|---|---|
| **1** | 대형 민간 페스티벌 — 워터밤·흠뻑쇼·펜타포트·자라섬재즈·렛츠락 등, 2026-09~12 | 15~25 |
| **2** | 예매처 「페스티벌」 카테고리 — 인터파크·예스24·멜론티켓·NOL 티켓 | 20~40 |
| **3** | 서울·경기 민간 축제 (심사 노출 빈도가 가장 높은 지역) | 20~30 |

### 브랜드 팝업은 담지 않는다 (2026-08-18 결정)

처음엔 배치 4로 넣으려 했는데, 뺀다.

이건 **한국관광공사 관광데이터 활용 공모전**이다. 심사위원이 보는 건 "관광 데이터를 잘 썼는가"인데, 백화점 팝업이 목록에 섞여 있으면 *관광 서비스인가 이벤트 모음인가*라는 질문이 생긴다. 우리 강점(데이터 신뢰·4개 언어·방문객 실측)과도 닿지 않는다.

경계는 이렇게 긋는다.

| | 담는다 | 왜 |
|---|---|---|
| 워터밤·펜타포트·옥토버페스트 | ✅ | 사람들이 **축제라고 부른다**. 외국인이 검색할 대상이기도 하다 |
| 유료 뮤직 페스티벌 | ✅ | 같음 |
| 브랜드 팝업 | ❌ | 축제가 아니라 마케팅이다. 「축제」의 경계는 우리가 지켜야 한다 |

배치가 셋으로 줄어 8/23 기한 안에 1~3에 집중할 수 있다.

---

### 배치 1에서 배운 것 (2026-08-18)

7건을 받아 전부 검증을 통과했지만, **두 가지를 우리가 고쳐야 했다.** 다음 배치 프롬프트에는 미리 박아 넣는다.

| 마누스가 준 것 | 실제 | 왜 위험한가 |
|---|---|---|
| `Oktoberfest Seoul 2026` | **옥토버페스트 서울 2026** | 공식 홈페이지가 스스로를 한국어로 쓴다. 한국어가 주인 화면인데 영문명으로 실으면 한국인이 검색해도 안 나온다 |
| 파라다이스시티 `중구` | **영종구** | 인천 중구는 영종구·제물포구로 나뉘었다. 그대로 넣으면 **화면에는 멀쩡히 보이면서 지역 필터에서만 빠진다** — 눈으로 안 잡히는 종류다 |

그리고 배치 1이 7건에 그친 이유가 있다. 프롬프트에 워터밤·흠뻑쇼를 예로 들었는데 **그건 여름 축제라 9~12월엔 없다.** 이름을 나열해 시키면 그 이름만 찾는다. 배치 2는 예매처를 훑는 방식이라 이름을 모르는 것까지 나온다 — 그쪽이 발견에 더 강하다.

## 6. 검증 관문 (여기서 하는 일)

마누스가 준 CSV를 그대로 싣지 않는다. 네 관문을 통과한 것만 들어간다.

1. **출처가 실제로 열리는가** — `sourceUrl`에 접속해 200이고, 그 축제 이야기가 맞는지 확인
2. **날짜가 공식 채널과 같은가** — 예매처와 주최측이 다르면 주최측을 따른다
3. **이미 있는 425건과 겹치지 않는가** — 이름·지역·기간으로 대조. 겹치면 버린다
4. **`confidence`가 `블로그`뿐인가** — 그렇다면 공식 채널을 찾아 확인, 못 찾으면 버린다

통과한 것만 `pipeline/data/seed/manual-festivals.json`에 넣는다. **`note` 필드에 언제 어디서 확인했는지 반드시 적는다** — 기존 20건이 그렇게 돼 있고, 나중에 "이건 왜 실렸지"를 답할 수 있는 유일한 근거다.

```json
{
  "externalId": "manual:oktoberfest-seoul-2026",
  "name": "옥토버페스트 2026 서울",
  "startDate": "2026-09-12",
  "endDate": "2026-09-21",
  "sido": "서울특별시",
  "sigungu": "마포구",
  "address": "서울특별시 마포구 증산로 87 문화비축기지",
  "fee": "일반석 평일 20,000원 / 주말 25,000원, 프리미엄존 테이블당 200,000원(4인)",
  "note": "2026-08-18 마누스 배치1 수집 → 주최측 공지로 날짜·요금 재확인. 공공 API 미등록 확인(TourAPI '옥토버' 0건)"
}
```

그다음 파이프라인을 돈다.

```bash
cd pipeline && npm run sync && npm run merge && npm run enrich && npm run translate && npm run push
```

## 7. 지속 장치 — 마누스 없이도 굴러가게

마누스는 8/23까지다. 그 뒤에도 새 축제는 계속 생긴다.

### E. 주최측 등록 창구

「축제를 등록해 주세요」 폼. 승인제로 받는다. 스팸 위험보다 얻는 게 크다 — **주최측이 직접 넣으면 데이터가 가장 정확하고, 그 접점이 나중에 광고·제휴의 입구가 된다.**

### F. 이용자 제보

이미 있는 「정보가 틀렸나요?」(`corrections`)에 **「빠진 축제 알려주기」** 유형 하나를 더한다. 테이블도 화면도 이미 있어서 두 시간이면 된다.

## 10. 다른 세션이 알아낸 것 — 라인업은 공공 API에 없다 (2026-08-18)

은미님이 축제 블로그(`blog.naver.com/break_eat`)가 어디서 정보를 받아오는지 물었고, 다른 세션이 본문·이미지·발행이력을 역분석했다. 결론은 공개 API가 아니었다.

```
① 지자체 보도자료 / 지역 언론   → 일정·프로그램·라인업 본문
② 축제 공식 인스타 / 주최 홈페이지 → 포스터·라인업 이미지
③ 예매처                       → 가격·예매 링크
```

근거가 단단하다. 8/15자 괴산고추축제 글의 세부 수치(가요제 예선 381팀→본선 9팀, 주차 400면, 셔틀 20분 간격)가 8/12 괴산군 보도자료 문구 그대로였고, 이미지 캡션에 `2026괴산고추축제 SNS`·`공주시청 홈페이지` 같은 출처가 그대로 박혀 있었다. 발행 시각이 제각각이라 크론도 아니다 — 수집은 사람이 하고 글쓰기만 AI다.

### 우리에게 중요한 것

**TourAPI·문화포털에는 출연진 라인업이 없다.**

음악 페스티벌에서 사람들이 실제로 검색하는 건 "누가 나오는가"인데 그게 공공 API로는 안 나온다. 방금 넣은 민간 페스티벌 15건이 대부분 음악 페스티벌이라 이 공백이 그대로 우리 공백이다. 자라섬재즈·부산국제록·그랜드민트 상세에 라인업이 없으면, 그 축제를 찾는 사람에게 우리 페이지는 예매처보다 못하다.

우리 스키마에는 `program` 필드가 이미 있다. 채우기만 하면 된다.

### 보도자료의 시간 이점

보도자료 공개부터 개최까지 **2~3주 여유**가 있다. 개최 3주 전 보도자료를 잡으면 어느 채널보다 먼저 정보를 갖는다. 시군청 새소식 RSS와 네이버뉴스 지역면이 실질적 1차 소스다.

다만 이건 상시 파이프라인 이야기이고 9/21 전에 만들 것은 아니다. 제천문화살롱에 유사한 수집 자동화가 이미 돌고 있으니 그때 그 코드를 재사용한다.

### 포스터는 여전히 받지 않는다

블로그는 공식 인스타에서 포스터를 퍼온다. 우리는 못 한다 — 공모전 제출물이고 저작권 처리가 안 된다. 지자체 홈페이지의 공공누리 표시를 확인한 것만 쓸 수 있다.
