# 언어 확장 메모

**2026-08-18 · 지금 결정하는 것이 아니라, 나중에 늘릴 때 꺼내 볼 메모**

---

## 참고한 것

관광 사이트의 언어 전환 목록을 봤더니 다섯이었다.

```
한국어 · 日本語 · English · 简体中文 · 繁體中文
```

배울 점은 **중국어를 간체·번체로 나눈다**는 것이다. 하나로 묶지 않는다. 쓰는 사람이 다르기 때문이다.

| | 쓰는 곳 |
|---|---|
| 简体中文 (간체) | 중국 본토 |
| 繁體中文 (번체) | 대만 · 홍콩 · 마카오 |

한국 인바운드에서 이 둘은 서로 다른 시장이다. 대만·홍콩 여행자에게 간체를 보여주는 건 성의 없어 보인다.

## 우리 현황

```ts
export const LANGS = ['ko', 'en', 'ja', 'th'] as const   // web/lib/i18n.ts
```

**중국어가 없고 태국어가 있다.** 태국어를 넣은 건 동남아 인바운드를 본 것인데, 방문객 규모로만 보면 중국어권이 먼저다. 다만 지금 바꿀 일은 아니다 — 이미 4개 언어로 번역이 다 돌아가 있고, 9/21 전에 판을 흔들 이유가 없다.

## 늘릴 때 손대는 곳

언어 하나를 늘리면 URL·번역·검색엔진이 함께 움직인다. 순서대로.

| | 파일 | 할 일 |
|---|---|---|
| 1 | `web/lib/i18n.ts` | `LANGS` 에 코드 추가 · `HTML_LANG`(BCP 47) · `LANG_NAME`(그 언어로 적는다) |
| 2 | `web/lib/ui.ts` | 화면 문구 사전 한 벌. 지금 언어당 약 150줄 |
| 3 | `pipeline/src/translate-llm.ts` | `required: ['id','en','ja','th']` 에 추가 후 전체 재번역 |
| 4 | `web/app/sitemap.ts` | 자동 — `LANGS` 를 돈다 |
| 5 | 상세 `alternates.languages` | 자동 — `LANGS` 를 돈다 |

3번이 비용의 대부분이다. 425건 × 새 언어 한 벌을 LLM으로 번역한다.

## 넣을 때 지킬 것

- **URL에 언어를 넣는다.** 이미 그렇게 돼 있다(`/ko/`, `/ja/`). localStorage로 언어를 기억시키면 검색엔진에 한 벌만 보이고 링크를 공유해도 상대는 다른 언어로 연다 — 이전 구현에서 실제로 겪은 일이다
- **언어 이름은 그 언어로 적는다.** 「중국어」가 아니라 `简体中文`. 자기 말을 찾을 수 있어야 한다
- **간체·번체를 하나로 합치지 않는다.** BCP 47 코드는 `zh-Hans` / `zh-Hant`
- 번역은 기계번역이 아니라 LLM으로 돌리되, 아는 사람에게 한 번 훑게 한다. 지금 en·ja·th 도 검수를 못 받은 상태다
