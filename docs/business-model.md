# KOTA 수익 구조와 API 설계

작성 2026-08-17. 근거: T맵 「가볼만한 축제」 실사용 관찰, 트립어드바이저 구조 분석, 자체 데이터 실측.

---

## 1. 우리가 가진 것 — 무엇을 파는가

축제 원본 데이터는 공공데이터라 **누구나 무료로 받는다.** 그러니 우리가 파는 건 데이터가 아니라 **쓸 수 있게 만든 상태**다.

| 우리가 더한 것 | 규모 | 남이 하기 어려운 이유 |
|---|---|---|
| 5개 소스 병합·중복 제거 | 원본 1,040 → 425건 | 소스마다 이름·날짜가 어긋난다. 「맥주축제」와 「동대문구 맥주축제」가 같은 축제임을 아는 데 규칙이 필요하다 |
| **4개 언어 번역** | 425 × 3언어 = 1,275건 | LLM 비용과 시간. 기계번역은 로마자 쓰레기를 낸다(실측) |
| **방문객 실측 배율** | 327건 | 관광공사 관광빅데이터(통신사)를 가공. 아무도 안 한다 |
| 이미지 확보·검증 | 274건 | 핫링크 차단까지 실측해 걸렀다 |
| **신뢰성 검증** | 유령 축제 263건 제거 | 「남원 워터밤」은 2024년이 마지막인데 여러 서비스가 지금도 예정으로 싣는다 |

마지막 항목이 핵심이다. **T맵도 「퍼스트가든빛축제 26.01.01~26.12.31」을 그대로 노출한다.** 1년 내내 열린다는 뜻이 아니라 날짜 미상이라는 뜻인데, 이용자는 아무 날이나 가도 되는 줄 안다. 우리는 이걸 「기간 중 일부 날짜」로 표시한다.

## 2. 수익 경로 — 셋

### ① 노출 광고 (검증된 시장)

T맵 「가볼만한 축제」 목록 최상단에 **「광고」 뱃지가 붙은 축제**가 있다. 축제 주최측이 노출을 사고 있다는 뜻이고, **시장이 실재한다는 실증**이다.

- 고객: 축제 주최측, 지자체 관광과
- 시점: 축제 두 달 전 ~ 개최 기간
- 우리 강점: 외국인 대상 노출은 우리만 판다(4개 언어)

다만 **T맵의 실수는 따라가지 않는다.** T맵 축제 상세에는 토익 앱 광고와 생필품 추천이 붙는다. 축제를 보러 온 사람에게 세제를 파는 순간 페이지는 잡화점이 되고 정보의 신뢰가 함께 깎인다. **광고를 넣더라도 축제·여행 문맥 안에서만.**

### ② 데이터 API (B2B)

| 고객 | 사는 이유 |
|---|---|
| OTA·여행사 (야놀자, 마이리얼트립) | 자사 앱에 축제 정보를 넣고 싶은데 정제 비용이 크다 |
| 항공사·호텔 | 인바운드 마케팅 — "9월에 한국 가면 뭐 있나"를 외국어로 |
| 지자체 | 자기 지역 축제의 타 지역 노출 |
| **AI 서비스 (MCP)** | AI가 "한국 축제 알려줘"에 답할 때 부를 곳이 없다 |

마지막이 가장 새롭다. MCP 서버로 열면 AI 비서가 우리를 데이터 출처로 쓴다.

### ③ 제휴 (장기)

축제 → 숙소·교통 연결. T맵이 「주변 갈 만한 장소」로 하는 것. 우리는 그 데이터가 없어 TourAPI 연동이 선행돼야 한다.

## 3. API 설계

### 팔 수 있는 것과 없는 것 — 먼저 가른다

라이선스를 섞으면 나중에 되돌릴 수 없다.

| 항목 | 출처 | 재배포 |
|---|---|---|
| 축제명·일정·장소·좌표 | 공공데이터 | ✅ 자유 |
| **번역 (en/ja/th)** | 우리 저작물 | ✅ 우리 권리 |
| **방문객 배율** | 우리 가공물 | ✅ 우리 권리 |
| **리뷰·평점** | 이용자 저작물 | ⚠️ 이용약관에 재배포 동의 필요 |
| TourAPI 이미지 | 공공누리 3유형 | ❌ 변경금지 — URL 참조만, 재호스팅 불가 |
| 주최측 스크랩 이미지 | 라이선스 없음 | ❌ 판매 불가. 우리 화면 표시만 |

**이미지는 API 상품에서 뺀다.** 대신 원본 URL과 출처를 함께 주고 사용 조건을 명시한다.

### 엔드포인트

```
GET /v1/festivals                  목록 — region, theme, from, to, lang, sort
GET /v1/festivals/{id}             상세
GET /v1/festivals/{id}/reviews     리뷰 (동의한 것만)
GET /v1/regions                    권역·시군구별 집계
GET /v1/insights/visitor-lift      방문객 배율 — 유료 티어 전용
```

### 요금 구간

| 티어 | 내용 | 월 |
|---|---|---|
| Free | 1,000회/월, 한국어, 출처 표기 필수 | 0 |
| Basic | 5만회/월, 4개 언어 | 유료 |
| Pro | 무제한, 방문객 배율, 웹훅 | 협의 |

Free를 두는 이유: 개발자가 먼저 써보게 하는 통로이자, 공공데이터 기반 서비스로서 최소한의 공공성이다.

## 4. T맵에서 배운 것과 버릴 것

### 가져올 것

| | 왜 |
|---|---|
| **앵커 탭** (홈·리뷰·사진·주변·정보) | 상세가 길어지면 필수. T맵 상세는 13,000px이 넘는다 |
| **D-5 뱃지** | 시작까지 남은 날. 「곧 열려요」보다 정확하고 행동을 부른다 |
| **오늘종료 뱃지** | 오늘 안 가면 끝. 카드에서 바로 보여야 한다 |
| **정보 수정 요청** | 이용자가 오류를 신고하는 창구. **우리 데이터 품질 문제를 이용자가 잡아준다** |
| **시간별 인기** | 언제 붐비나. 우리는 통신사 데이터가 있어 T맵보다 잘할 수 있다 |
| 별점 분포 막대 | 리뷰가 쌓이면 |

### 버릴 것

| | 왜 |
|---|---|
| 문맥 무관 광고 (토익 앱) | 축제 정보의 신뢰를 깎는다 |
| 생필품 커머스 끼워팔기 | 페이지가 잡화점이 된다 |
| 연중 기간 그대로 노출 | T맵의 실수다. 우리는 이미 「기간 중 일부 날짜」로 처리했다 |
| 13,000px 상세 | 앵커 탭이 있어도 과하다 |

## 6. 정면 승부는 지고, 옆에서 이긴다

T맵은 우리가 못 가질 것을 가졌다. **「7대 가는 중」** — 지금 그 축제로 향하는 차량 수. 내비를 가진 자만 아는 숫자다. 「지금 가는순」 정렬도 마찬가지다.

그러나 T맵은 **한국어뿐이다.** 외국인이 한국 축제를 찾을 때 T맵을 켜지 않는다. 그리고 T맵에게 축제는 내비의 부가 기능이라, 데이터 품질에 우리만큼 공을 들일 이유가 없다(연중 표기를 그대로 두는 게 그 증거다).

우리 자리는 여기다.

- **외국인 인바운드** — 4개 언어. 경쟁이 국내 검색의 1/10도 안 된다
- **데이터 신뢰** — 열리지 않는 축제를 싣지 않는다
- **방문객 실측** — "얼마나 몰리는가"에 숫자로 답한다

## 7. SK open API — 붙일 수 있는 것과 지금은 아닌 것

T맵 「가볼만한 축제」의 뒷단이 여기 있다(openapi.sk.com). 우리와 맞닿는 상품:

| 상품 | 무엇 | 우리에게 |
|---|---|---|
| **장소 혼잡도** | 특정 장소가 언제 붐비나 | T맵 상세의 「시간별 인기」가 이것. **"언제 가면 덜 붐비나"는 여행자가 진짜 원하는 정보다** |
| **유동인구** | SKT 기지국 기반 인구 이동 | 우리 방문객 배율의 직접 소스. 지금은 관광공사가 가공한 것을 무료로 쓴다 |
| **국내 여행** | 여행 관련 데이터셋 | 내용 확인 필요 |
| TMAP | 지도·경로·POI | 지도 대안. 다만 카카오맵이 국내 인지도가 높다 |
| 장소·음식점·주거 | 상권 데이터 | 「주변 갈 만한 장소」를 만들 재료 |

### 지금은 붙이지 않는다 — 세 가지 이유

1. **이미 같은 성격의 데이터를 무료로 쓰고 있다.** 관광공사 관광빅데이터(통신사 방문자수)가 그것이고, 방문객 배율 327건이 거기서 나왔다. 유동인구를 새로 사도 얻는 게 겹친다.
2. **유료이고 기업 계약이다.** 개인 개발자가 카드로 긁어 쓰는 구조가 아니다. 견적·계약에 시간이 든다.
3. **9/21 이전에 새 외부 의존을 늘리는 건 위험하다.** API 하나가 죽으면 그 화면이 죽는다.

### 언제 붙이나

**장소 혼잡도는 수익이 생긴 뒤 1순위**다. "이번 주말 진주남강유등축제, 토요일 오후 8시가 가장 붐빕니다"는 우리가 못 만드는 정보이고, 그걸 만들면 축제 정보 서비스가 아니라 **여행 계획 도구**가 된다.

그전까지는 우리가 가진 것으로 비슷한 답을 낸다 — 지난 회차 방문객 배율은 "얼마나 몰리는가"에는 답하고, "언제 붐비는가"에는 아직 답하지 못한다. 이 구멍을 아는 상태로 두는 것과 모르는 것은 다르다.

## 8. 순서

1. **행동 로그 수집** ✅ 2026-08-17 시작 — 소급 불가라 가장 급했다
2. **정보 수정 요청** 창구 — 데이터 품질을 이용자가 함께 지킨다
3. **API 문서 공개** — 실제 판매 전에 개발자가 볼 수 있게
4. 광고 자리 설계 — 축제·여행 문맥 안에서만
5. MCP 서버 — AI가 우리를 부르게

당장의 수익보다 **팔 수 있는 상태를 만드는 것**이 먼저다. 지금 API를 상품화하지 않더라도, 우리 웹이 그 API를 쓰게 만들어 두면 외부에 여는 일은 문을 하나 더 내는 것으로 끝난다.
